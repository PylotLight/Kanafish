# Japanese TTS for Kanafish: options and a learner-first test

## Short answer

I could not identify a Japanese speech product named **“Phorus TTS”** from exact-name searches. The closest plausible name is **Fish Audio**: its current S2.1 model explicitly lists Japanese among its strongest languages and offers an API. “Phorus” alone mostly surfaced unrelated speaker products, so this is a likely spelling or hearing mix-up, not a confirmed identification.

Four local models now have real download-and-synthesis paths in Kanafish: **Supertonic 3** through ONNX Runtime WebGPU/WASM, **NVIDIA Magpie Multilingual v2607** through an optional Japanese-enabled NeMo-Speech.cpp native runtime, **Qwen3-TTS 0.6B CustomVoice** through optional codec.cpp, and **Irodori-TTS v4.1-Small** through an optional app-managed Python sidecar. Qwen uses its built-in Japanese Ono Anna preset and a checksum-pinned Q8_0 pair; its CPU path is slow and its Mac Metal path is untested. Irodori’s 3.50 GB checkpoint/codec is checksum-pinned and its CPU path is also slow. Python is installed only for Irodori, never required by the other engines. The cloud-provider comparison below remains future research, not a runtime shipped by the app.

## Current local pilot

- **Supertonic 3**: four Japanese samples on sandbox CPU, ONNX Runtime 1.23.1, eight denoising steps; measured RTF was 0.21–0.46 and sessions loaded in 1.23 seconds. The in-app model is downloaded only when requested (about 399 MB); weights remain outside Git and use OpenRAIL-M, while the adapted helper code is MIT-licensed. The project is archived, so version pinning is important.
- **NVIDIA Magpie Multilingual v2607**: four matching Japanese samples ran on sandbox CPU with official NeMo-Speech.cpp v0.3.0 built with HTTP and `NEMO_SPEECH_TTS_WITH_JA=ON`. The local service loaded in 2.12 seconds; RTF was 1.42–1.56. Its model, tokenizer and NanoCodec stack occupied 668,084,511 bytes (about 637 MiB). Kanafish caches these files only when requested. The NeMo runtime code is Apache-2.0, but Magpie weights are under the separate NVIDIA Open Model License.
- **Qwen3-TTS 0.6B CustomVoice**: the actual codec.cpp adapter discovered the tested native server, verified both pinned model files and generated a Japanese WAV with `ono_anna` through the app’s loopback-service code. The integration smoke test took 6.93 seconds to generate 2.24 seconds of audio (RTF 3.09); the four-line CPU benchmark was 3.44–6.06× real time. Its GGUF pair is 1,949,930,688 bytes (about 1.82 GiB); Kanafish downloads it only on request and verifies exact sizes and SHA-256 hashes. Model weights are Apache-2.0 and codec.cpp is MIT. The owner’s Mac/Metal path is not tested.
- **Irodori-TTS v4.1-Small**: the integrated Kanafish Node-to-Python CPU path generated `こんにちは。` and passed RIFF/WAVE validation at 48 kHz. The app-side measurement was 11.55 seconds to load the model and codec, then 8.09 seconds to generate 1.48 seconds of audio (RTF 5.47). The separate four-line Python benchmark ran at 3.11–6.02× real time. Kanafish offers explicit Python setup, model download and separate model-cache/Python-environment removal controls; weights stay outside Git. MPS has not been tested. The JavaScript/WebGPU investigation remains relevant as a non-Python alternative: its v4.1-Small-MF duration-graph probe did not produce audio, and the available WebGPU pipeline targets v3. SilentCipher is optional upstream; it is not installed in Kanafish, so this build does not add its watermark to generated audio.
- **ASR transcription proxy, not a quality score**: local faster-whisper small (CPU int8) transcribed all 12 clips, with normalized mean character error rates of 8.8% for Supertonic, 8.8% for Irodori, and 12.0% for Magpie. All three scored 25% on the time/numbers line because the proxy writes kanji numbers as Arabic digits and the comparison does not convert number styles. Magpie’s dialogue clip scored 23.1%; its transcript missed much of the coffee-order phrase. This warrants a human listen, not a quality verdict. No human listening review has been performed; ASR transcription is not a pronunciation or naturalness score.
- **Not supported in this build**: MioTTS requires an LLM server, a separate codec and Python service; Qwen3-TTS Base still lacks a verified preset-voice path; Chatterbox is retired and unmaintained. These remain research cards, not selectable or downloadable models.
- **Apple GPU status**: WebGPU is a browser API that may use platform graphics APIs such as Metal; it is not native PyTorch MPS. NeMo's and codec.cpp's Metal backends are separate native C++ paths. Irodori requests PyTorch MPS when available, with a CPU fallback. The owner’s Mac was unavailable, so Kanafish on macOS, Metal and MPS have not been tested.

## What matters for a conversation learner

A useful course voice should pronounce the lesson's Japanese accurately, sound clear at everyday speed, handle names/numbers and polite phrases consistently, and offer a slower replay without making slow speech the only version a learner hears. A natural voice matters, but clear phrasing and dependable pronunciation matter more than dramatic expressiveness for early listening.

A good later player flow is: **listen once at normal pace with text hidden → answer a gist/detail question → replay at a slower setting if wanted → reveal kana and meaning → replay by phrase**. Keep kana available beside speaking and listening. Do not use slowed audio as a substitute for normal-speed examples. For fairness, compare the same short test set across providers: greetings, polite questions, long vowels, small っ, numbers/prices, station and place names, and a two-speaker dialogue. Have a proficient Japanese speaker check pronunciation and a beginner judge intelligibility.

### How to read the costs

These are provider-published USD list prices reviewed on **17 November 2026**, before taxes and any account/region differences. Free allowances are conditional and can change. One million characters is far more than the short static dialogues in an early course pilot, so voice clarity, Japanese pronunciation, stable voice identity, and integration constraints likely matter more than a small price difference. Fish Audio bills by UTF-8 bytes and ElevenLabs by credits, so their headline figures are not a like-for-like per-character comparison.

## Recommendation

1. **Use Amazon Polly Neural as the first controlled baseline** for a small technical audition because it documents fine rate control and Japanese-specific pronunciation support. Test Takumi, Kazuha, and Tomoko rather than assuming a single default voice is best.
2. **Compare Google Chirp 3 HD** on the exact same clips for naturalness and learner intelligibility. Its multiple Japanese voices and published free allowance make it a useful quality comparison; retain it only if the difference is audible and valuable.
3. **Audition Fish Audio S2.1 Pro** if that is the product you had in mind. Check natural Japanese delivery on calm, everyday travel dialogue—not only expressive demos—and clarify API commercial terms before using it in a public app.
4. **Keep TTS behind a provider adapter** rather than binding lesson content to one vendor. A future interface can take locale, text, voice ID, rate, optional speaker/lexicon, and return audio plus any available timing marks. Keep credentials outside the Electron renderer; if mobile is supported, use a protected backend or a device voice rather than embedding a provider key in the app. Cache stable course audio by content/model/voice/rate and allow a generated-audio-free fallback.
5. **Do not implement speech recognition or speaking evaluation as part of this choice.** First validate listening activities and the human-readable can-do checks. A later TTS pilot can be limited to listen, replay, slow, and reveal-kana controls.
