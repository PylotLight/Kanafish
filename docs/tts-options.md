# Japanese TTS for Kanafish: options and a learner-first test

## Short answer

I could not identify a Japanese speech product named **“Phorus TTS”** from exact-name searches. The closest plausible name is **Fish Audio**: its current S2.1 model explicitly lists Japanese among its strongest languages and offers an API. “Phorus” alone mostly surfaced unrelated speaker products, so this is a likely spelling or hearing mix-up, not a confirmed identification.

Only **Supertonic 3** is selectable in the current Kanafish interface. It includes all ten official voice presets (M1–M5/F1–F5), runs with ONNX Runtime WebGPU/WASM, and downloads model files on demand. Voice Lab can keep one voice, rotate by week or lesson, or shuffle per listen; lesson rotation is stable on replay and keeps one voice throughout a dialogue. The other five local integrations described below are hidden and disabled after the live setup showed only Supertonic working there; their code and earlier sandbox validation notes are retained for re-testing, not presented as currently available choices. Those earlier tests do not establish that the engines work on the owner's live device. Model weights stay outside Git. The cloud-provider comparison below remains future research, not a runtime shipped by the app.

## Current local pilot

- **Supertonic 3**: four Japanese samples on sandbox CPU, ONNX Runtime 1.23.1, eight denoising steps; measured RTF was 0.21–0.46 and sessions loaded in 1.23 seconds. The in-app model plus ten voice styles is downloaded only when requested (about 401 MB); weights remain outside Git and use OpenRAIL-M, while the adapted helper code is MIT-licensed. The project is archived, so version pinning is important.
- **NVIDIA Magpie Multilingual v2607**: four matching Japanese samples ran on sandbox CPU with official NeMo-Speech.cpp v0.3.0 built with HTTP and `NEMO_SPEECH_TTS_WITH_JA=ON`. The local service loaded in 2.12 seconds; RTF was 1.42–1.56. Its model, tokenizer and NanoCodec stack occupied 668,084,511 bytes (about 637 MiB). Kanafish caches these files only when requested. The NeMo runtime code is Apache-2.0, but Magpie weights are under the separate NVIDIA Open Model License.
- **Qwen3-TTS 0.6B CustomVoice**: the actual codec.cpp adapter discovered the tested native server, verified both pinned model files and generated a Japanese WAV with `ono_anna` through the app’s loopback-service code. The integration smoke test took 6.93 seconds to generate 2.24 seconds of audio (RTF 3.09); the four-line CPU benchmark was 3.44–6.06× real time. Its GGUF pair is 1,949,930,688 bytes (about 1.82 GiB); Kanafish downloads it only on request and verifies exact sizes and SHA-256 hashes. Model weights are Apache-2.0 and codec.cpp is MIT. The owner’s Mac/Metal path is not tested.
- **Irodori-TTS v4.1-Small**: the integrated Kanafish Node-to-Python CPU path generated `こんにちは。` and passed RIFF/WAVE validation at 48 kHz. The app-side measurement was 11.55 seconds to load the model and codec, then 8.09 seconds to generate 1.48 seconds of audio (RTF 5.47). The separate four-line Python benchmark ran at 3.11–6.02× real time. Kanafish offers explicit Python setup, model download and separate model-cache/Python-environment removal controls; weights stay outside Git. MPS has not been tested. SilentCipher is optional upstream; it is not installed in Kanafish, so this build does not add its watermark to generated audio.
- **Irodori-TTS v4.1-Small-MF ONNX**: the separate MeanFlow-distilled model is app-managed and uses JavaScript tokenization with ONNX Runtime WebAssembly, no Python. The integrated CPU smoke test generated a valid, non-silent Japanese WAV; the first run took 12.78 seconds for 1.20 seconds of audio (RTF 10.65) including model loading. This verifies the pipeline, not naturalness; Mac/WebGPU and human-listening tests have not been performed. See the [runtime guide](tts-runtime.md) for the pinned assets and license notes.
- **MioTTS-0.6B**: the integrated CrispASR native C++ CPU path used the pinned Q4_K checkpoint and Japanese preset to generate a valid, non-silent WAV in 2.81 seconds for 0.60 seconds of audio (RTF 4.68, including process/model startup). The model and codec licenses are separate from the preset's non-commercial output restriction. Mac builds and human listening have not been tested. See the [runtime guide](tts-runtime.md) for platform support and license details.
- **ASR transcription proxy, not a quality score**: local faster-whisper small (CPU int8) transcribed 12 clips from Supertonic, Irodori and Magpie. Transcription errors can reflect number formatting and recognition limits, so this is not a pronunciation or naturalness score. The owner has separately preferred Supertonic in listening comparisons; that does not constitute a controlled comparison of every engine.
- **Not available in this build**: Qwen3-TTS Base still lacks a verified preset-voice path; Chatterbox is retired and unmaintained. These are not selectable or downloadable models.
- **Apple GPU status**: WebGPU is a browser API that may use platform graphics APIs such as Metal; it is not native PyTorch MPS. NeMo's and codec.cpp's Metal backends are separate native C++ paths. Irodori requests PyTorch MPS when available, with a CPU fallback. The owner’s Mac was unavailable, so Kanafish on macOS, Metal and MPS have not been tested.

## What matters for a conversation learner

A useful course voice should pronounce the lesson's Japanese accurately, sound clear at everyday speed, handle names/numbers and polite phrases consistently, and offer a slower replay without making slow speech the only version a learner hears. A natural voice matters, but clear phrasing and dependable pronunciation matter more than dramatic expressiveness for early listening.

The course player now supports a listen-first flow: **hear the dialogue at normal speed with kana and English hidden → optionally replay more slowly → reveal kana and meaning → continue to comprehension and response practice**. Individual lines, Japanese phrase-bank entries, reply choices, kana/kanji readings, review cards, and phrasebook cards can also be played. Keep normal-speed audio available; slowed speech is an optional aid, not a replacement. Validate additional engines with a proficient Japanese speaker and beginner listeners before treating their audio as equivalent to the current preferred voice.

### How to read the costs

These are provider-published USD list prices reviewed on **17 November 2026**, before taxes and any account/region differences. Free allowances are conditional and can change. One million characters is far more than the short static dialogues in an early course pilot, so voice clarity, Japanese pronunciation, stable voice identity, and integration constraints likely matter more than a small price difference. Fish Audio bills by UTF-8 bytes and ElevenLabs by credits, so their headline figures are not a like-for-like per-character comparison.

## Recommendation

1. **Keep Supertonic 3 as the only currently enabled engine.** Expose all ten bundled styles with a learner-selectable fixed/week/lesson/shuffle pattern; normal-speed playback remains available alongside the slower lesson replay.
2. **Keep the other five local engines disabled and hidden until live validation.** Their sandbox measurements do not establish that they work on the owner's device, and macOS/Metal performance should not be assumed.
3. **Make model licenses and preset restrictions visible.** In particular, do not use audio generated with MioTTS's bundled Japanese presets commercially.
4. **Keep model weights and runtimes outside Git and on-demand.** Retain non-audio alternatives so a learner can continue when no selected local engine is ready.
5. **Keep speech recognition and automated speaking evaluation out of scope.** Validate the implemented listening flow and task-level outcomes with Japanese-speaking reviewers and beginner learners instead.
